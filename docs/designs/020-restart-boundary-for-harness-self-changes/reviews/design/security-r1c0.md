## Findings

- [major][new] Chosen design §1 — "runs `git diff --name-only <headBefore>..HEAD`, filters it through the predicate" (and Options considered: "`git diff --name-only <window start>..HEAD` taken once in each finalize window") — the canonical detection command omits the NUL-separation and rename-disabling flags this repo already established as mandatory for path lists. `runner.ts`'s own helpers carry the lesson (`porcelainPaths` doc, runner.ts:247-259: "NUL separation means paths are never quoted or escaped, `--no-renames` means a rename is never collapsed into one pseudo-path (`old -> new`)"; `nulPaths` at runner.ts:261-264 exists exactly for flagless diff listings). Implemented as written, the predicate can silently miss: default `core.quotePath` prints non-ASCII/special-byte paths quoted-and-escaped, so a crafted or exotic name like `tools/orchestration/src/prömetheus.ts` arrives as `"...pr\303\266metheus.ts"` and fails a prefix match; and with default rename detection a rename-out of the two prefixes shows one collapsed spelling that matches no prefix. Every path in the range is model-authorable (the ownership matrix at gates.ts:575-582 gives `implement`/`fix` the whole `tools/orchestration/**` set), and a miss opens no boundary — the run drives on with the stale renderer, the exact run-016 class this design exists to close. The §7 honesty test does not catch it: the missed path is under a named prefix. Fix: change §1's (and Options') canonical call to `git diff -z --no-renames --name-only <headBefore>..HEAD`, parsed with the existing `nulPaths` helper — same posture as the sweep's `diff-tree … -z --name-only` at runner.ts:308; one flag pair, replaces the quoted-listing form wholesale.

- [minor][new] Chosen design §2/§3 — "gate-logs a `restart-boundary` entry naming the stage and hit paths … mints a terminal `chore: <nnn>-<slug> restart boundary` commit whose body names the changed paths … It prints the one-line summary §3 names" — the design never says the model-authorable path strings are sanitized or bounded where they are written. The established posture is writer-side: `gateLog` runs every reason through `printable` (runner.ts:2006-2023) and `planStopStatusLines` prints through it (runner.ts:3586), with the comment at independence.ts:434-445 naming "paths and command text" as attacker-chosen data that "would otherwise spoof or corrupt the terminal line"; and every collection the checkpoint clones is writer-capped (`boundedFindings`, `boundedGateEvidence`; state-store.ts:43: "Size bounding is the writer's job"). The boundary's gate-log entry and status line inherit those printables, but the printed summary and the commit body name the paths raw, and `paths: string[]` is unbounded in the record. A crafted control byte in a path spoofs the operator's terminal and the `git log` the operator reads. Fix: one clause in §2 — the record, summary, and commit body take each path through `printable`, and the record keeps the `boundedGateEvidence` posture (first N paths plus the count, which §3's status line already prints) — naming those two existing helpers, adding no mechanism.
