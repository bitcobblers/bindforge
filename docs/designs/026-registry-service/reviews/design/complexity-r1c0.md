## Findings

- [major][new] §Options considered ("the harness carve-out is the honest cost, not the format choice") + §The seed corpus + §Catalog document and its spec ("`schemas/catalog/v1/` ships `spec.md` + `fixtures/valid/*.json`") — the named file list for the JSON carve-out (common/mod.rs, conformance.rs, version_gate.rs, schemas/README.md) misses a second shipped consumer of the very same trees: `crates/discovery/tests/boundary_tests.rs::the_shipped_corpus_carries_no_source_key_spelling` walks **every file under `data/` recursively** plus every `schemas/*/v*/fixtures/valid/` and fails if any contains the literal `steam/`, `epic/` or `local/` (its `walk_files` recurses; the assertion is `violations.is_empty()`). Because `Source::spells_lookup_key` (crates/discovery/src/game.rs:84) admits only those three tokens, **no** valid catalog document can exist under those trees: the `026-S1` seed that "each carr[ies] its `steam/<appid>` `source_key`", and every valid `schemas/catalog/v1/fixtures/valid/*.json`, both trip it. `T-004` as scoped therefore cannot land green under `cargo test --workspace --locked`, and the options comparison priced the choice on an incomplete cost — the sweep covers `data/` too, so the rejected "just don't put it in `schemas/`" alternative would not have dodged it either. Fix: add the amendment to that same bullet list — re-scope that sweep to `data/manifests`/`data/profiles` (or exempt `data/catalog/` and `schemas/catalog/v1/fixtures/`), re-pin its doc-comment and its `checked > 0` guard, and restate the Options paragraph's cost with the two harness consumers named. `026-S1` mandates the keys, so the sweep moves, not the seed.

- [major][new] §`apps/registry` — one crate, two modes ("It depends on `bindforge-core` for the grammar and name bounds") + §Caching mode ("reuses the shipped client's response discipline with its own private constants") + §CLI amendment ("mirroring `parse_endpoint`") + §Deferred ("pinned by the same `StoreLayout` env-closure seam") — this language describes sharing the crate layout cannot give: `apps/discovery-cli` is a bin-only crate (`apps/discovery-cli/Cargo.toml` declares no `[lib]`; `apps/` holds only `src/{main.rs,catalog.rs,matches.rs}`), so the response reader/count caps, `parse_endpoint`, `game_id_is_valid` (matches.rs:354), `StoreLayout`/`data_dir`/`store_path` (matches.rs:46–103) and the tmp-and-rename `save`/`owner_only_new_file` discipline are **unreachable** from a new `apps/registry` crate — the design therefore ships a second copy of five shipped invariants and defers the lift for exactly one of them. Conversely the one validator that *is* importable, `Source::spells_lookup_key`, lives in `crates/discovery`, a dependency the dependency sentence never names. Fix: in §Chosen design replace "reuses"/"mirroring"/"the same … seam" with one short shared-vs-copied list naming, per block (response discipline, endpoint gate, `game_id` predicate, `<data>` rule, atomic persist, source-key spelling), whether the task lifts it to a shared crate (`bindforge-core` or a small new one) or duplicates it with a pinning test; and state the real dependency line for `apps/registry` (`bindforge-core` + `discovery` + `serde_json`). Smaller design: lift the three store/IO blocks once and have both binaries call them — that removes three duplicate invariant sets and the "second copy of the env-closure seam" the Compatibility matrix and Test #13 rely on.

- [minor][new] §Budgets ("`MAX_REQUEST_BODY_OCTETS` (a POST body cap)") + the same section's "`fetched_at` that is not a non-negative integer within a plausible-clock bound") — two of the design's own refusal thresholds are named without a value, while Test strategy #11 ("`MAX_REQUEST_HEADER_OCTETS`/`MAX_REQUEST_BODY_OCTETS` refusals") and #4 ("a `fetched_at` outside the load bound is refused") pin behavior against them. A section whose stated goal is that "budgets close against each other" cannot establish that for an unvalued cap, and the task author has to invent the number the proposal exists to decide. Fix: state both numbers in the same sentence (e.g. body cap `= 65_536` mirroring the header cap; `fetched_at` accepted within `[now − horizon, now + skew]`, both named), and cite them from #4/#11 by value rather than by constant name alone.

- [minor][new] §Caching mode ("Upstream **reachability** (the `health.upstream` gauge) is gauged by the upstream's own `/v1/health`, but that verdict is **cached and refreshed on the same TTL**") — no trigger is named for that refresh, and the module plan (`main`/`serve`/`http`/`corpus`/`admin`/`cache`/`upstream`/`endpoint`/`constants`, `serve.rs` = "accept loop (one thread per connection, request-read timeout)") contains no scheduler. So either the `/v1/health` probe never runs — leaving `health.upstream` derived only from lookup outcomes, which is not the `026-C6` clause the section cites — or a background timer arrives as an unplanned tenth moving part. The same paragraph then claims "A cold query therefore does **not** pay a separate upstream health round trip", which only holds while the verdict is unexpired. Fix: one sentence naming the trigger — "the probe runs at most once per TTL, fired lazily by the first lookup after expiry on the request's own thread; there is no timer thread" — and adjust the round-trip claim to "no *additional* health round trip per query beyond the one TTL-gated probe".

- [minor][new] §CLI surface ("overridable by `--local-entries <path>`", "`--refresh-interval` overrides `026-B3`") — neither knob has a consumer anywhere in the Test strategy: #14 pins only `--upstream`, #16 passes `--corpus`, #13 reaches the paths through the env seam, and no item starts a caching instance with a relocated entries file or a shortened TTL. `--refresh-interval` is `026-B3`-mandated, and `--local-entries` is design-invented beyond `026-C1`'s flag list, so the design pays for two knobs it never exercises. Fix: extend #6 or #17 with one clause each — a TTL override that makes a cached entry expire early, and a caching run with `--local-entries` pointed at a scratch path proving the admin mutation lands there — or drop `--local-entries` and let the test use `HOME`/`XDG_DATA_HOME` like #13 already does.

- [nit][new] §Catalog document and its spec ("guard `every_valid_fixture_…`, `every_invalid_fixture_…` and the single-line/truncation loops behind the core-TOML check") — of the loops named, only `every_valid_fixture_re_serializes_to_a_semantically_equal_value`, `every_invalid_fixture_is_rejected_with_a_structured_error` and `every_invalid_fixture_is_rejected_with_a_single_line_message` walk the fixture tree; the truncation case (`a_rejection_truncates_an_untrusted_value_rather_than_echoing_it`) parses a hand-built document and needs no guard, so following this text adds a dead conditional. The list also omits the call site the `.json` rule actually needs: `fixture_file_names_are_lowercase_ascii_dash_separated_and_case_unique` asserts `is_fixture_name(name)` for every file in the tree, and `is_fixture_name` takes a bare name with no directory/format argument. Fix: name the three walking loops plus the fixture-name test, drop "truncation", and say whether `is_fixture_name` gains a format argument or the call site is guarded.

- [nit][new] §Catalog document and its spec ("recognize a small `EXTERNAL_JSON_FORMATS = ["catalog"]` set") + §Risks ("pin it with a test that the list is the single source") — this builds a general external-format registry plus a meta-test about the list's own use, for exactly one member. Smaller: one `const` naming `catalog` at the skip site, with the `schemas/README.md` paragraph as the record; add the generalization when a second JSON format actually arrives. Keep as written only if the panel wants the forward-compat on the record.

## Value check (checklist item 7)

Proportionate overall: every section maps to a named `026-C`/`026-L`/`026-B`/`026-S` unit, the three `Options considered` rejections each name the precedent they lean on, the private-budget choice avoids growing core's constant family, and `Rollout` already sequences the whole service across five tasks so nothing here lands at once. The two majors are both about cost the document under-counts rather than machinery the design adds for its own sake: one shipped gate it must amend and does not name, and five invariants it copies rather than shares while describing them as shared.
