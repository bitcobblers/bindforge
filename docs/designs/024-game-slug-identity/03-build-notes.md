## Deviations from the proposal

- **Refusal wording is split by fault kind, not one template.** The proposal
  (§2, §7) asks every slug refusal to end with the offending value, and
  `escape_and_truncate` (which that wording depends on) cuts an echoed value at
  80 octets. A slug-bound corpus test then requires the *bound* to survive in the
  message, which the offender's own length makes impossible for an over-long
  offender. Bound faults therefore state the bound first and then the value;
  shape faults keep the proposal's wording. This is the trade the shipped code
  already makes — `crates/core/src/input.rs` prints `` `{id}` exceeds the {max}-octet
  identifier limit ``. No test pins the wording of a slug-bound refusal beyond
  `octets: 128`/`129`.
- **Action-id segment faults are split into two named faults** (length bound vs
  character shape). Previously one predicate produced one message for both, so a
  200-octet segment's refusal named `Move.Forward` last and the corpus test that
  requires `Move.Forward` to be visible could only be satisfied by hiding the
  bound. Both arms are still enforced on both segments;
  `test_segment_bound_enforced_on_action_and_instance` and
  `test_overlong_component_refused` pass.
- **Fixture rename rather than in-place edit.**
  `schemas/action-ids/v1/fixtures/invalid/segment-past-63-octets.toml` is
  re-pinned to one octet past the new cap and renamed to `segment-past-cap.toml`
  via `moves`. The proposal's "update in place" is not possible because the
  superseded filename is itself a pinned negative condition
  (`the_superseded_segment_bound_fixture_is_out_of_the_corpus`), and copying to
  the new path instead would leave a stale 64-octet-name fixture that the raised
  bound now accepts, breaking `conformance.rs`. The stage cannot rename files.
