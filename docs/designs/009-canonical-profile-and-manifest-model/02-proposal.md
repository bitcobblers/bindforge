# Design: ADR-009 — Canonical profile, transform, and manifest model

## Context

ADR-009 ([docs/adrs/009-canonical-profile-and-manifest-model.md](../../adrs/009-canonical-profile-and-manifest-model.md)) fixes five contracts, numbered 1–5 in the order listed: an action taxonomy, an input vocabulary with per-hand reach classes, profiles expressed as chains, composable transform policies, and game manifests. `schemas/` is the public contract, and `crates/core` + `crates/transforms` the reference implementation. This design turns those five contracts into files, entry sets, typed APIs, and a reviewed data seed, building on [01-research.md](./01-research.md).

What the repo already fixes, and what this design must respect rather than re-decide: ADR-008 shipped the workspace (`crates/core`, package `bindforge-core`, depends on nothing), the `schemas/` contract tree with a **documented subset** of TOML v1.1.0 whose v1 grammars refuse table headers, dotted keys, multi-line arrays, floats, and hex integers, the closed per-format entry sets, the version gate, the 1 MiB / 16-level / 32-link adversarial guard, and the fixture-walking conformance harness. Two consequences drive most of the design: a dotted taxonomy id used as a bare TOML key *is* nested-table syntax the grammar refuses, so the id encoding is a load-bearing decision (research Q1); and the harness requires a reader for every `schemas/*/v*/` directory, so every new format is parsed in `bindforge-core` (A8). Assumption ids A1–A25 below are local to this proposal.

## Goals / Non-goals

- Goals:
  - The five contracts defined as versioned format specs plus golden fixtures, machine-checkable by the existing harness with no harness change.
  - Concrete Rust: modules, types, function signatures, and the `crates/transforms` package and its dependency edge.
  - Deterministic chain resolution and a shipped `diff`, with the `fork`/`merge` rules stated as the patch contract (ADR Decision 3).
  - Placement legality computed from data, not prose (Decision 2).
  - Manifest validation that cross-checks the taxonomy, and a CI mechanism that surfaces game-patch drift as a visible failure (Decision 5).
  - A reviewed seed: the taxonomy's first id set, graded reach tables, placements, one Remnant 2 manifest, one base + patch chain, one policy.
- Non-goals:
  - Anything the Deferred / out of scope section assigns to a named owner — ADR-012's codecs and CLI, ADR-011's preset set, ADR-014's hub, and layout generation (this design reserves only the `generated-by` field).
  - Any input-event API (injection, capture), any UI, any ISO/JIS or non-US-layout tables, and gamepad binding modeling.

## Options considered

**Id encoding in TOML: dotted bare keys, quoted ids, pair tables, or a separator change.** Bare `move.steer-left = …` is nested-table syntax the v1 grammar already refuses with a fixture (A1, A12), so it is not available; inline pair tables (`{action = …, input = …}`) are refused for the same reason, and a separator change mangles ids that are a compatibility promise (`/` is not a legal bare key at all; `move_steer-left` is a permanent rename of every published id). Chosen: **an id is a quoted-key entry** — legal under A2, one line per fact, diff-friendly, and the id's dots never become TOML structure. Rejected: the rest.

**Chain field: keep `derives`, add `based-on`, or both.** ADR-009's sketch spells one parent (`based-on`); the shipped contract carries an ordered ancestor list (`derives`, nearest first) that `resolve_chain` reads, and a shipped valid fixture carries two ancestors. Adding `based-on` as a second spelling creates two sources of one fact that can disagree. Chosen: keep `derives`, and state once that the ADR's `based-on` is `derives[0]`. Rejected: add `based-on`; keep both.

**Document version: `version = "1.0.0"` (ADR sketch) vs the shipped gate.** The gate compares `version` to the supported majors and rejects `1.0.0` (A4); widening the gate to a dotted revision breaks the majors-equal-dirs rule (008 Test strategy #2) and the never-defaulted rule. Chosen: `version` stays the format major; the manifest's own `<major>.<minor>` revision is a separate `revision` entry — the only document revision that exists, and the only thing a pin can name. Rejected: widen the gate.

**Patch op encoding: quoted-key map + `clear`/`swap` arrays, an RFC 6902-style ordered op list, or positional parallel arrays.** An op list (`[["replace", …], …]`) is expressive but makes every document order-sensitive, which is what makes "fork, tweak, merge" lossy (A14). Positional parallel arrays (`actions = [...]`, `inputs = [...]`) mispair silently on a hand edit. Chosen: deltas keyed by quoted action id, with `clear` and `swap` as separate entries, at most one touch per action per document, and a pinned cross-kind order — order stops mattering, so documents stay readable and merges commute (see Chosen design → Profiles are chains).

**Merge of two patches on one base: three-way (git model) vs reject-on-overlap.** Three-way merge needs the common ancestor's deltas, rename detection, and a CLI to present conflicts; none of that is load-bearing for the model, and the CLI is ADR-012. Chosen: overlap is a rejection (`MergeConflict`); legal merges require disjoint touched-action sets — deterministic with no implicit winner. Rejected: three-way (deferred).

**Placement legality: curated placement data + computed checks, runtime geometric mirroring, or a review-only claim.** Mirroring is the ADR's own rejected option (it scatters cluster members). "Shape preserved, reviewed by a human" leaves the ADR's legality verdict uncomputed, so two implementations could disagree. Chosen: a placement is key→key data; the reach tables carry US-ANSI grid coordinates, so isometry and the reach bound are both computed in `bindforge-core` (see Chosen design → Reach classes and placements).

**Axis kind location: canonical in the taxonomy, canonical in the manifest, or both.** Taxonomy-only cannot express a game that exposes a look axis as a key; manifest-only leaves transforms with no rule to enforce before any manifest exists. Chosen: canonical in the taxonomy, the manifest re-declares it, and disagreement is a rejection (`AxisKindConflict`) — one canonical statement plus a cross-check. Rejected: both-canonical (drift).

**`crates/core` dependencies: keep it dependency-free, or follow the ADR's '(serde-based)' parenthetical.** ADR-009 says core implements the formats serde-based. `bindforge-core` is the depends-on-nothing root (A9), `serde` is staged in the workspace for a later consumer (A10), and the closed entry sets, budget, and version gate are hand-written rules serde's derives cannot express (A10). Adding serde to core buys nothing here: the accepted grammar is a subset, and the reader already enforces it. Chosen: core stays dependency-free; a consumer that wants serde data models (ADR-012's codecs) reaches them through `toml_edit`. This is a stated deviation from one word of the ADR, taken deliberately.

## Chosen design

### Encoding rules (canonical)

Every new format obeys the shipped grammar (A1, A2) and adds nothing to it:

- **Ids are quoted keys.** Bare keys are metadata entry names only. No bare key contains `.`; every id that names an entry — taxonomy action id, input id, profile/patch/policy/placement id — appears as a quoted key (`"move.steer-left" = "keyboard:a"`), so the dotted-key collision (research Q1) cannot arise in any format. Ids that are *values* (in `derives`, `clear`, `presets`, axis arrays, `game`) are the same strings in the same grammar.
- **Three id shapes.** Taxonomy ids: `[a-z0-9-]+(\.[a-z0-9-]+)*` (dots only here). Game ids: the same shape with no dot (`remnant2`), which excludes `..`, `/`, `\`, and a leading `.` — this grammar, not a path rule, is what gates a pin's halves. Input ids: `<namespace>:<part>`, `<namespace>` ∈ `keyboard|mouse|gamepad`, `<part>` = lowercase words joined by `-` (never a dot, never a `*`); `pos` joins that closed set only in a v2 of every format carrying input ids, so a v1 document naming `pos:a` is `UnknownInput`. `*` appears only in a policy action pattern, as a trailing suffix on a non-empty literal prefix (`move.steer-*`), and a pattern matching zero actions is a reported `Skipped`, not a quiet no-op.
- **`version` is the format major** (`v1`) for every document, per the gate (A4). A document's own revision is a `<major>.<minor>` string in `revision`, and the only document that carries one is a `manifest/v1` — the ADR's `for = "remnant2@0.1"` pins `game = "remnant2"` + that manifest's `revision`, in the same grammar, so every pinnable revision is nameable.
- **Nested arrays for structured lists.** `[[a, b]]` is legal TOML (A13) and the reader accepts it at nesting level 2, inside the 16-level budget (A6): `stack`, `swap`, and the manifest's `action`/`default`/`exclusive` rows are each a leading id (action, group) followed by its values, so no entry set ever relaxes into a prefix rule. The one string-embedded tuple is the reach row's fixed `"<class> <row> <col>"` triple.
- **Round-trip.** Every format's `fixtures/valid/` re-serializes to an equal value, which is exactly what the unmodified harness does to every format (A8) — `reach-classes` alone is load-asserted, because its loader consumes a per-hand directory pair, not one document. Seed data that lives outside `fixtures/` (`actions.toml`, `{left,right}.toml`) is load-checked by the model tests.
- **No id becomes a path** (see Profiles are chains and Manifests state game facts).

### 1. Action taxonomy — `schemas/taxonomy/v1/` + `crates/core/src/taxonomy.rs` (new)

Lookup data, in the contract tree beside the reach tables: `schemas/taxonomy/v1/spec.md` and `schemas/taxonomy/v1/actions.toml`:

```toml
format = "taxonomy"
version = "v1"
"move.steer-left" = "discrete-lateral"
"move.strafe-left" = "discrete-lateral"
"aim.camera" = "continuous-lateral"
"combat.melee" = "none"
```

Entries: `format`, `version`, then one quoted-key entry per action id whose value is its axis kind — `discrete-lateral`, `continuous-lateral`, or `none`. The taxonomy is **canonical for axis kind**; a manifest that re-declares it differently is rejected (Options). `spec.md` carries the id grammar by reference to the canonical Encoding rules, states the closed axis-kind set, and states that ids are added only by manifest-review PRs: an id in the wild never churns, and removal is a major bump. The seed ships ~40 ids covering third-person shooter / ARPG needs for the Remnant 2 exercise (`move.*`, `aim.*`, `combat.*`, `interact.*`, `item.*`, `ui.*`, `system.*`). No `gamepad.*` id is minted (ADR: reserved, unmodeled).

API: `Taxonomy::load(path: &Path) -> Result<Taxonomy, CoreError>` pinned to the one data file (`schemas/taxonomy/v1/actions.toml`), mirroring how `load_reach_tables` pins `{left,right}.toml` (A7) — `spec.md` states that `fixtures/` is harness input and never load input — plus `is_known(&self, id: &str) -> bool`, `axis_kind(&self, id: &str) -> Option<AxisKind>`, `ids(&self) -> &[ActionId]`, and `AxisKind::{DiscreteLateral, ContinuousLateral, None}`.

**Emphasis is not in the taxonomy, and is not authored in the manifest either** (canonical statement): the game fact is the action's default input, recorded as a manifest `default` row (contract 5), and "emphasis" is the reading of that input's reach class for the hand that owns it. The taxonomy never claims a natural position for an action.

### 2. Input vocabulary, reach classes, placements

**Input vocabulary** (canonical; `schemas/README.md` states it beside the encoding rules, since it is an identity rule every format shares): `keyboard:<name>` names a US-ANSI key by glyph for `a-z0-9` and by key name for everything else — `keyboard:semicolon`, `keyboard:apostrophe`, `keyboard:space`, `keyboard:shift-left`; `mouse:left|right|middle|side-1|side-2|wheel-up|wheel-down`; `gamepad:<part>` is a reserved, unmodeled namespace whose shape is frozen now (research Q4) — `<part>` is one hyphen-joined lowercase token, so a future scheme can adopt W3C "standard gamepad" part names (A20) without a shape change. Physical-position naming (the layout-independent scancode axis, A17) is reserved by shape: it arrives as a *new* prefix (`pos:<part>`) admitted only by a v2 of every format that carries input ids (Encoding rules), leaving `keyboard:` meaning "US-ANSI glyph" permanently. `schemas/README.md` carries the admitted keyboard-name list: the `keyboard:` vocabulary the reach tables draw from, enforced by the reach loader (a key outside it is `InvalidValue`), and carrying no grading obligation of its own — the graded set below is content-derived, and that is the enumeration Test strategy #3 iterates. No second key-name table is invented here.

**Reach classes** extend the shipped tables in place — `schemas/reach-classes/v1/{left,right}.toml`, loaded by the shipped `load_reach_tables` (A7):

```toml
format = "reach-classes"
version = "v1"
hand = "left"
classes = ["home", "stretch", "far", "thumb", "off-reach"]
"keyboard:a" = "home 1 1"
"keyboard:w" = "stretch 0 3"
```

- `classes` is the vocabulary, and its **table order is the degradation rank** (rank 0 = nearest). The ADR's five grades are the v1 vocabulary.
- A quoted-key entry grades one input for that hand: `"<class> <row> <col>"`, three space-separated fields, class ∈ `classes`, row/col signed decimal integers on the US-ANSI grid (A17). Grading and geometry in one table, one loader, one review.
- Loader rules, added to `reach.rs`: every class string is in the declared vocabulary; every key is a `keyboard:` id in the admitted list, else `InvalidValue`; the file's name agrees with its in-file `hand` (one source for the hand fact); **a key present in both tables carries identical coordinates** (`GeometryConflict`); classes may differ between hands — that is the ADR's asymmetry claim, expressed as data. `ReachTable::class_of(input)` and `ReachTables::rank(hand, input)` are added, defaulting a key the hand's table does not carry to `off-reach`, the vocabulary's last rank — that makes the emphasis reading total for any input a manifest `default` row names; a table is a **graded set**, not the keyboard. The shipped per-hand distinctness (008 Test strategy #4) is preserved.

**Placements** — `schemas/placement/v1/spec.md` (format) and `data/placements/*.toml` (curated content), `crates/core/src/placement.rs` (new):

```toml
format = "placement"
version = "v1"
id = "wasd-to-oksemike"
hand = "right"
max-degrade = 1
"keyboard:w" = "keyboard:i"
"keyboard:a" = "keyboard:o"
"keyboard:s" = "keyboard:k"
"keyboard:d" = "keyboard:l"
```

`validate(placement, &ReachTables) -> Result<(), CoreError>` computes the ADR's two legality conditions: **shape** — the offset vectors between source keys equal the offset vectors between the target keys (isometry), else `PlacementNotIsometric`; **reach bound** — for every pair, `rank(hand, target) − rank(hand, source) ≤ max-degrade`, else `PlacementDegraded`; a key the hand's table does not grade has no coordinates to compare, so shape rejects it as `UnknownInput`. `wasd-to-ijkl` and `wasd-to-oksemike` both ship as legal placements, and the "OKL; keeps the home-row anchor, IJKL does not" claim (A16) is *not* prose in this design: it is whatever `validate` and the graded tables report, and the fixtures record that verdict.

**Authoring bar** (research Q2; canonical): grading is authored judgment with no external ground truth (A15), so the review is the contract. `placement/v1/spec.md` and `reach-classes/v1/spec.md` state the checklist a grading PR must satisfy, and CI enforces what it can: the graded set — every key the shipped placements and the seed manifest's `default` rows reference, extended only by review — is graded in both hands, coordinates agree across hands, grades are non-decreasing in grid distance from that hand's home-graded keys, every rejected condition is pinned by Test strategy #3's model tests — `reach-classes/v1/fixtures/invalid/` carries only the parse-refusable cases (Adversarial posture) — and every grading change carries a named reviewer (`git log`). The class vocabulary and its order are frozen for v1 — a re-grade of a published grade is `reach-classes/v2`, and every shipped placement verdict is re-checked by Test strategy #3 and #4.

### 3. Profiles are chains — `schemas/profile/v1` (extended), `schemas/patch/v1` (new), `crates/core/src/{index.rs,resolve.rs}` (new)

A base is a `profile` document; a delta is a `patch` document (the format split `schemas/README.md:3-13` already anticipates). Content lives in `data/profiles/**/*.bindprofile`, one document per file.

`profile/v1` entry set grows by **optional** entries only, so the shipped valid fixtures stay valid (no narrowing): `for` (the pin, `"<game>@<revision>"`, split at the first `@`, its halves validated against the game-id grammar and the `<major>.<minor>` revision grammar, else `BadPin`; absent = a profile not bound to a game, which is what serves the ADR's accessibility and alternative-controller case), `seeded-from` (a preset name the pinned manifest declares; **requires `for`** — with no pin there is no manifest to check it against, so a `seeded-from` with no `for` is `InvalidValue`), `generated-by` (an id in the `<namespace>:<part>` shape whose namespace is a **closed producer list** — `policy|preset|generator` — never an input namespace, e.g. `policy:lefty-mouse-relocate`; a value outside the shape is `InvalidValue`, so a shared profile publishes no free-text attribution — binding an id to a person is ADR-014's, A22). `format`, `version`, `id`, `derives` keep their shipped meaning; **`based-on` is `derives[0]`**, no alias entry is added, and a profile carries no `revision` of its own: chain identity is `id` + `derives`, and the only pinnable revision is a manifest's.

`patch/v1` requires the same `format`, `version`, `id`, `derives` entries as a base, carries the same optional chain entries, and adds deltas: quoted-key set entries (`"move.steer-left" = "keyboard:a"`), `clear = ["move.strafe-right"]`, and `swap = [["move.strafe-left", "move.strafe-right"]]` (A13).

Resolution (canonical chain semantics; `crates/core/src/resolve.rs`):

- Documents are applied **deepest ancestor first** (the base), then up the list to the document itself. Inside one patch, the order is pinned and does not depend on author line order: all `swap`, then all `clear`, then all `set`, each in the reader's sorted key order (the reader's map is a `BTreeMap`, `crates/core/src/toml.rs:98-105`, so the traversal is byte-deterministic across platforms).
- **A patch touches each action at most once** (across set/clear/swap), else `DuplicateDelta`. Together with the pinned order, this removes the RFC 6902 non-commutativity problem (A14) at the document level: the order inside a document is fixed, and the order *between* documents is the chain.
- API: `resolve(index: &Index, root: &str, rung: usize) -> Result<Resolved, CoreError>` with `Resolved { bindings: BTreeMap<ActionId, InputId>, chain: Vec<String>, manifest: Option<ManifestPin> }`, whose `manifest` is `Some` whenever the profile declares `for`; `rung` is the ADR's "mount at any rung" (`rung = chain.len()` takes the whole chain, `rung = 1` takes the base alone). `resolve` also rejects a `seeded-from` the pinned manifest does not declare, naming the profile id — a profile fact read against a manifest, so not `validate`'s; the pin's index lookup, and the `UnresolvedAncestor` for a pin naming no manifest document, are canonical in Id → file.
- `diff(a: &Resolved, b: &Resolved) -> PatchDoc` emits set/clear deltas and ships in the first slice. `fork` (`resolve(root, rung)` + `diff` against the full chain, i.e. an adopter's independent patch) and `merge` — legal **iff the two patches' touched-action sets are disjoint**, overlap is `MergeConflict` naming both patch ids and the shared actions, with no implicit winner — are the algebra `patch/v1/spec.md` states as the format contract, and land with their suite in the ADR-012 slice that has the caller (research Q3; three-way merge Deferred).
- Chain guard: the shipped `resolve_chain`, `Cycle`, `ChainTooDeep`, and `MAX_CHAIN_DEPTH` are reused unchanged (A5), and the tuning the ADR permits resolves to no change. The unit is one `derives` entry, so `MAX_CHAIN_DEPTH = 32` accepts 32 links — a base plus 32 patches, 33 documents — far past any chain this seed authors, and the bound is not removable.

**Id → file, never id → path** (research Q7, A18): `crates/core/src/index.rs` walks `data/profiles/` and parses every document, indexing by its **declared** `id`; `data/manifests/` gets the same treatment, keyed on each document's declared `game` + `revision`, so a `for` pin is an index lookup and no path is ever built from a document string. Each tree accepts only the formats it holds — `data/profiles/` `profile`/`patch`, `data/manifests/` `manifest` — and a document declaring another is rejected with the shipped `InvalidValue` naming the tree, since the key that tree indexes by is absent from it. The walk is bounded by two new public constants beside the shipped ones — `MAX_INDEX_ENTRIES`, `MAX_INDEX_DEPTH` in `index.rs`, re-exported from `lib.rs`, with seed-scale headroom (A25) — rejected as `IndexTooLarge` / `IndexTooDeep`, and an entry is taken by its own type (`DirEntry::file_type().is_file()`, symlinks not followed) with the size cap applied to bytes read from the opened file (`parse_reader`'s take-N shape, A6), not to `metadata` length, which a symlink to `/dev/zero` or a FIFO slips past. Ids are only ever string-compared, so `..`, absolute paths, and encoding tricks cannot reach the filesystem at all — and the shipped fixture whose id carries escapes stays valid. `UnresolvedAncestor` fires on any document reference with no document — a `derives` entry, **or a `for` pin whose `game` + `revision` names no manifest document in the index**, which is what makes `Resolved.manifest` `Some` whenever the profile declares `for` and keeps the `seeded-from` check and the drift gate from running against nothing. `DuplicateId` fires on two documents declaring one id, and on two manifest documents declaring one `game` + `revision` — an ambiguous pin key would make the drift gate's verdict walk-order dependent. File names follow the shipped fixture-name **stem** rule (lowercase ASCII, `-`-joined), with the extension stated separately (`.bindprofile` for profile/patch content; `.toml` for `schemas/` fixtures and for the `data/` manifest, placement, and policy documents), which keeps the tree tidy without making ids path components. Provenance (`seeded-from`, `generated-by`) labels the chain and gates nothing (ADR Decision 3): validation and adoption are the only trust mechanisms, and signature verification is ADR-014's (A22).

### 4. Transforms produce bases — `crates/transforms` (new), `schemas/policy/v1/` (new)

`crates/transforms`, package `bindforge-transforms`, is the workspace's first dependency edge: `bindforge-transforms → bindforge-core` (A9, ADR-008's graph). Files: `src/lib.rs`, `src/policy.rs`, `src/registry.rs`, `src/relocate.rs`, `src/polarity.rs`, `src/mouse.rs`, `tests/policy_semantics.rs`.

`schemas/policy/v1/spec.md` (parsed by `bindforge-core`, because the harness requires a reader for every format directory — A8):

```toml
format = "policy"
version = "v1"
id = "lefty-mouse-relocate"
stack = [["relocate-cluster", "move.steer-*", "right", "wasd-to-oksemike"], ["swap-polarity", "move.strafe-*"]]
```

Entries: `format`, `version`, `id`, `stack` — an ordered array of invocations, each a non-empty array of strings whose first element is the transform name. This spec carries the **closed invocation table** — each v1 transform's name, arity, and per-argument grammar (hand ∈ `left|right`, a placement id, a trailing-`*` action pattern) — as part of the format contract. core's reader owns only the `stack` shape, and `schemas/policy/v1/fixtures/invalid/` covers exactly what it can see: the refused-TOML cases and a bad `stack` shape. `apply_policy` validates the whole `stack` against the table — its registry carries exactly that table — before the first invocation runs, and a mismatch returns the shipped `InvalidValue { key, message }` naming the invocation as its `Err`. There is no policy-level `hand` (the invocation carries it, as ADR-009 spells it) and no opt-in knob: a policy enables a transform by listing it, which is the ADR's default-off. Example content lives in `data/policies/`.

`bindforge-transforms` interprets the stack: `apply_policy(base: &Resolved, policy: &PolicyDoc, ctx: &Ctx) -> Result<PolicyOutcome, CoreError>` with `PolicyOutcome { base: Resolved, skipped: Vec<Skipped> }` and `Skipped { transform: String, reason: String }` — `skipped` reports an *inapplicable* transform only, so a table rejection is the `Err` channel and a caller never reads "stack rejected" as "applied with skips" — over `Ctx { taxonomy: &Taxonomy, reach: &ReachTables, placements: &Placements }`. Its registry holds exactly that table, and:

- `relocate-cluster <action-prefix> <hand> <placement-id>` — precondition, computed on shipped data: the matched actions' current inputs in `base` are isometric to the named placement's source-key set (same offset vectors, per `placement::validate`'s shape rule over `<hand>`'s table); the move is that validation plus key substitution. Precondition failure, a rejected placement, or a pattern that matches no action → `Skipped` with a reason, base untouched.
- `swap-polarity <action-prefix>` — taxonomy-gated: only actions whose axis kind is `discrete-lateral` (ADR Decision 1); a `continuous-lateral` match is `Skipped`, so a policy can never key-swap camera look.
- `swap-mouse-buttons()` — no arguments; `mouse:*` names parse everywhere (contract 2) and applying them to a game is codec work (ADR-012).

An inapplicable transform reports itself and no-ops, so `apply_policy` returns `Ok(outcome)` with `skipped` populated when the stack is accepted, and no transform writes outside a base. Patch documents are never rewritten by a transform: they sit above the base in the chain and are re-applied unchanged after base regeneration (Test strategy #11).

### 5. Manifests state game facts — `schemas/manifest/v1/`, `data/manifests/`, `crates/core/src/manifest.rs` (new)

Format `schemas/manifest/v1/spec.md`; content `data/manifests/<game>/manifest.toml` — `<game>` follows the game-id grammar (Encoding rules) and the stem rule (contract 3), and the directory layout is cosmetic: a pin is resolved through the manifest index, never by joining a pin into a path:

```toml
format = "manifest"
version = "v1"
game = "remnant2"
revision = "0.1"
codec-family = "remnant2-ini"
fingerprint = ""
action-discrete-lateral = ["move.strafe-left", "move.strafe-right"]
docked = ["system.pause"]
dead-keys = ["keyboard:caps-lock"]
presets = ["left-handed", "right-handed"]
# …one row per bindable action; the fragment shows one of each role
action = [["move.steer-left", "Steer Left"]]
default = [["combat.melee", "keyboard:f"]]
exclusive = [["ui", "ui.map", "ui.inventory"]]
```

Entries: `format`, `version`, `game`, `revision`, `codec-family` (an id only — codecs are ADR-012), `fingerprint` (optional string; the field exists, the recipe is ADR-012's, A21), `action-discrete-lateral` / `action-continuous-lateral` (id arrays that **re-declare** the taxonomy's axis kind for the ids they name; an id in neither array inherits the taxonomy's kind, so the arrays cannot under-claim anything), `docked` (actions the game hard-docks), `dead-keys` (inputs the game ignores), `presets` (built-in preset names; their *content* is read by a codec, ADR-012), then the three nested-array rows of the Encoding rules: `action` = `[id, game-native name]` (the join), `default` = `[id, input]` (the emphasis fact, contract 1), `exclusive` = `[group, id…]`. The entry set stays the shipped closed allow-list — no prefix rule.

`validate(manifest, &Taxonomy) -> Result<(), CoreError>` enforces: every referenced id is known; a manifest's axis-kind claim equals the taxonomy's (`AxisKindConflict`); every `exclusive` and `docked` member appears in the `action` rows; every `default` value is a valid input id. That membership check is `docked`'s only v1 consumer — honoring a docked action is apply-time work owned by ADR-012 (Deferred).

**Drift mechanism** (canonical, Decision 5): a profile pins `for = "<game>@<revision>"`. The `cargo test` gate resolves every profile in `data/profiles/` against the manifest revision it pins — a read of the manifest index — and re-runs `validate` plus the `seeded-from` check; a manifest bump that drops an action a patch touches, re-declares an axis kind, puts two members of one `exclusive` group on one resolved input, or drops a preset a profile names fails the run, naming the profile id and the manifest revision — game-patch drift as a build failure, not a mid-game surprise. Bumps that make a *published* profile invalid are reviewed PRs; the hub re-running the same check on upload is ADR-014's (no ADR file, A23).

### Adversarial posture for the new formats (supports Decisions 3 and 5)

Every new format is read through the shipped `parse` / `parse_file` / `parse_reader` path, so the 1 MiB pre-read cap, the 16-level nesting cap, the closed entry sets, and the bounded one-line rejection messages apply unchanged (A3, A6, A8) — and every new format ships invalid fixtures for the refused-TOML constructs, including `dotted-key.toml`, because a reader built on a standard TOML parser accepts them and must refuse them. New `CoreError` variants are pinned by a `fixtures/invalid/` document **only where `parse` can see the condition** — the refused-TOML constructs, over-nesting, over-size, unknown entry, `BadPin` — and otherwise, over fixture data, by the model suite that calls their producer: the two index limits by Test strategy #1's synthetic walk; `GeometryConflict` by #3; `PlacementNotIsometric` and `PlacementDegraded` by #4; `DuplicateDelta` by #6; `AxisKindConflict`, `UnknownAction`, `UnknownInput` by #8; `DuplicateId` and `UnresolvedAncestor` by #9, which are two-document and index-level, so no single fixture can carry them; and `MergeConflict` lands with `fork`/`merge` in the ADR-012 slice, which is where its producer is. The set: `UnknownAction`, `UnknownInput`, `DuplicateDelta`, `DuplicateId`, `UnresolvedAncestor`, `MergeConflict`, `AxisKindConflict`, `GeometryConflict`, `PlacementNotIsometric`, `PlacementDegraded`, `BadPin`, `IndexTooLarge`, `IndexTooDeep`; a malformed policy invocation reuses the shipped `InvalidValue` — `stack`'s shape at parse, the invocation table's arity and grammars as `apply_policy`'s `Err` (contract 4) — so no transform runs with a bad argument. The per-document budget is unchanged and `MAX_CHAIN_DEPTH` is reused as is; the tree walk adds the two public constants `MAX_INDEX_ENTRIES` / `MAX_INDEX_DEPTH` (contract 3, A25), and `schemas/README.md`'s guard section gains those two constants and their rejections beside the shipped three, so its "public names for these limits" claim stays true. No rejection message carries a local path (shipped rule, `crates/core/src/error.rs:59-76`).

## Test strategy

1. Unit — grammar and budget for every new format directory: each `fixtures/invalid/` case is rejected with the pinned `CoreError` variant, including the refused-TOML-construct cases (dotted key, table header, multi-line array, float, hex integer), over-nesting, over-size, and unknown entry, and a walk over a synthetic tree with more than `MAX_INDEX_ENTRIES` entries or deeper than `MAX_INDEX_DEPTH` is `IndexTooLarge` / `IndexTooDeep`; each `fixtures/valid/` document parses and re-serializes to an equal value for every format — `profile`, `patch`, `manifest`, `taxonomy`, `placement`, `policy` — with `reach-classes` alone load-asserted, and the seed `actions.toml`/`{left,right}.toml` asserted by their loaders. No fixture directory is empty (A8).
2. Unit — taxonomy: every id matches the id grammar; ids are unique; every axis kind is in the three-value set; `axis_kind` and `ids` are deterministic; `load` reads `actions.toml` and never `fixtures/`; the seed id set is present in full and never shrinks between runs (a removal must fail the suite).
3. Unit — reach tables: the shipped per-hand distinctness obligation holds unchanged (008 Test strategy #4); every key entry parses as `<class> <row> <col>` with the class in the declared vocabulary; a key graded in both hands carries identical coordinates, and a `{left,right}` pair that breaks this fails as `GeometryConflict` in the loader, not in a fixture document; the two hands' grades differ for mirrored keys (the asymmetry claim is data); every key in the graded set — the keys the loaded `data/placements/` and the seed manifest's `default` rows reference — is graded in both hands, a key outside a hand's table reads as that hand's `off-reach`, and a reach-table key outside the admitted keyboard list is `InvalidValue`.
4. Unit — placement legality: every placement in `data/placements/` passes `validate`; a non-isometric fixture is rejected `PlacementNotIsometric`; a fixture exceeding `max-degrade` is rejected `PlacementDegraded`; a fixture naming a key the hand's table does not grade is rejected `UnknownInput`.
5. Unit — chain resolution: resolution applies documents deepest-ancestor-first; a chain of exactly `MAX_CHAIN_DEPTH` `derives` links (a base plus 32 patches) resolves and one link deeper is `ChainTooDeep`, written against the constant (008 Test strategy #3 preserved); a self-deriving chain is `Cycle`.
6. Unit — pinned op order and single-touch: a patch whose deltas are authored in three different line orders resolves to the same map; a patch touching one action in both `set` and `clear` is `DuplicateDelta`; `swap` observed before `clear`, `clear` before `set`; an unknown action id is `UnknownAction`, an unknown input value is `UnknownInput`, a malformed `for` pin is `BadPin`, a `generated-by` outside the `<namespace>:<part>` shape or whose namespace is outside the closed producer list is `InvalidValue`, and a `seeded-from` with no `for` is `InvalidValue`.
7. Unit — chain algebra round-trips: `resolve(index, root, rung)` for `rung = 1` equals the base alone and for `rung = chain.len()` the whole chain, and `diff(base, target)` re-applied to `base` reproduces `target` (`fork`/`merge`'s suite lands with them in the ADR-012 slice).
8. Unit — manifest validation: a manifest naming an unknown action id, an axis kind that disagrees with the taxonomy (`AxisKindConflict`), an `exclusive` or `docked` member absent from the `action` rows, or a `default` row whose input is not a valid input id is rejected, each with its own fixture.
9. Unit — ids never become paths: a document whose `id` or `derives` entry is `../../etc/x`, an absolute path, a case variant, or a control-character string resolves by index lookup only, reading no file outside the walked tree; a `for` pin whose game half is `..`, absolute, dotted, or dotted-revision is `BadPin`, and a valid pin resolves to a manifest by index lookup on declared `game` + `revision`; `DuplicateId` fires on two documents declaring one id, and on two manifest documents declaring one `game` + `revision`; `UnresolvedAncestor` on a missing `derives` document **and on a well-formed `for` pin that names no manifest document in the index**; a manifest-format document planted in `data/profiles/`, and a profile-format document in `data/manifests/`, are `InvalidValue` at index time; the shipped escape-carrying id fixture still resolves through the index.
10. Unit — policy and transform semantics: a stack invocation with the wrong arity, a hand outside `left|right`, a placement id that is not id-shaped, a bare `*` or a `*` anywhere but trailing on a non-empty prefix, or an unknown transform name is an `Err(InvalidValue)` from `apply_policy`, before the first invocation runs, and the registry's names, arity, and argument grammars equal the `policy/v1/spec.md` invocation table; `swap-polarity` on a `continuous-lateral` match is `Skipped` and the base is byte-for-byte unchanged; a `relocate-cluster` whose matched inputs are not isometric to the placement's source keys is `Skipped` with a reason and leaves the base untouched; a pattern matching zero actions yields a named `Skipped`; a stack's invocations are applied in declared order.
11. Integration — model walk over the seed: taxonomy + reach tables + placements + `data/manifests/remnant2/manifest.toml` + one base + one patch chain resolve to the expected binding map, and `apply_policy(game-default, policy:lefty-mouse-relocate)` with the player's patch above it yields the expected map; regenerating the base leaves the patch's deltas applied unchanged (a transform never rewrites a patch). The walk and drift suites build one `Index` per test binary and share it, so the gate is linear in files, not tests.
12. Integration — manifest-drift CI: bumping the seed manifest's `revision` (and, in a fixture, dropping a patched action, re-declaring an axis kind, creating an exclusivity collision, and dropping a preset a profile's `seeded-from` names) fails the run, naming the profile id and the manifest revision, for every profile that pins it.
13. Integration — harness pickup and the version gate: adding the five new `schemas/*/v1/` directories requires no change to `crates/core/tests/conformance.rs`, the walk exercises all of them, and `supported_majors()` equals the majors present under `schemas/*/v*/` (008 Test strategy #2 preserved).
14. Platform — all of the above is green on the Linux CI runner and on a Windows contributor machine (case-insensitive filesystem, `BTreeMap`-ordered resolution, no cwd, no network, no database — 008 Test strategy #5's precondition preserved).

Extend `crates/core`: `taxonomy.rs`, `placement.rs`, `manifest.rs`, `index.rs`, `resolve.rs`; the `Document` variants **and their `serialize` arms**, so every format's valid fixtures round-trip under the unmodified harness; the entry sets and the `CoreError` variants named in Adversarial posture; the `reach.rs` key-row and coordinate rules; `index.rs`'s `MAX_INDEX_ENTRIES` / `MAX_INDEX_DEPTH`. No new dependency, no per-document budget change, `MAX_CHAIN_DEPTH` unchanged.
3. Create `crates/transforms` (package `bindforge-transforms`, dependency `bindforge-core` via `[workspace.dependencies]`) with the registry — each entry exactly its `policy/v1/spec.md` row, name, arity, and argument grammars — and the three transforms; add its tests mirroring `src/` per ADR-004.
4. Author the seed data in reviewable slices, each with its fixtures: (a) the graded reach tables, both hands, over the graded set, (b) the two placements, (c) the ~40 taxonomy ids, (d) the Remnant 2 manifest at `revision = "0.1"`, (e) one base + one patch chain, (f) one policy in `data/policies/`. Each slice lands with the test that grades it.
5. Add the model-walk, manifest-drift, and transform-semantics suites (Test strategy #10, #11, #12) as `crates/core/tests/{model_walk.rs,manifest_drift.rs}` and `crates/transforms/tests/policy_semantics.rs`, sharing one `Index` per test binary; run `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --locked` — the existing gate, no new workflow.
6. Record in the two data `spec.md` files the authoring bar and the review requirement (named reviewer per grading PR); the data-homes rule lands in `schemas/README.md` (Files created), not in a second place.
7. Verify the Windows leg of Test strategy #14 on a contributor machine before announcing the model, and record the outcome in the run's build notes.

Migrations: none — no document is in the wild (A11), and the `profile/v1` entry additions are optional, so every shipped fixture resolves unchanged. Defaults: `derives = []`, `for` absent = not bound to a game, an action absent from a manifest's axis arrays inherits the taxonomy's kind, a key absent from a hand's reach table is that hand's `off-reach`, `derives` naming nothing = a standalone base.

- Which policies ship as the seed preset set, and preset naming/quality rules — ADR-011 (planned).
- Hub storage and schema, upload gate, wire-level budget enforcement, server-side chain pre-resolution, signatures/checksums as the trust mechanism behind `generated-by` (A22), voting and adoption ranking — ADR-014 (planned).
- Where a player's personal policy document lives on their machine — ADR-009 leaves it open; no follow-up file exists (A23), and this design sets no location.
- ISO/JIS reach tables and the layout-independent `pos:` key naming (A17) — no follow-up yet; needs a layout axis in the reach-table file shape plus a v2 of every format carrying input ids (Encoding rules).
- Gamepad binding modeling (the reserved `gamepad:` namespace) — no follow-up yet; the id shape is frozen here so later naming needs no format break.
- Three-way merge with common-ancestor reconciliation and rename detection — no follow-up yet; the shipped rule is disjoint touched-action sets.
- A machine-checkable schema language for the TOML formats (research: the TOML→JSON mapping makes JSON Schema expressible) — no follow-up yet; the fixtures remain the contract (A8).
- Emphasis recorded in the manifest as anything richer than the game's default input, and per-action "invertible by a game option" flags (research Q8) — no follow-up yet; the option's existence is a game fact a codec can read (ADR-012), Returnal-style (A19).
- Layout generation (AI or heuristic) and its ranking — no follow-up yet; this design ships only the `generated-by` field it needs.
- Mouse `wheel-*` semantics beyond naming, DPI/acceleration, and non-keyboard accessibility devices (foot pedals, sip-and-puff) — no follow-up yet.
