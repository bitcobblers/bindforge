## Findings

- [blocker][new] §1 Chosen design "Fence runner-reserved paths in the ownership matrix" — "`stagePathAllowed(stage, path)` (`gates.ts:260–273`) gains a first rule that precedes the per-stage rules: return `false` when the path's last segment is `STATE_FILE`" — the fence is placed in the same predicate `enforceOwnership` uses to build its violation set over *all* touched paths (runner.ts:260–261: `committed` paths from the runner's own in-window commits plus `dirtyFiles`), and the sweep is author-agnostic — which is exactly A3's cited basis. At every stage-boundary sweep the checkpoint is dirty by the runner's *own* save: pass-seat writes are drained before the sweep (runner.ts:1871), and `checkpoint()` runs again right after the commit (runner.ts:2298, 2336), so the first fenced rule flags every legitimate runner save and `restore --source=headBefore` rolls it back. Consequences the document contradicts: (a) mid-run boundary commits never advance the committed checkpoint again (each sweep restores the file identical to HEAD before `git add -A`), making A7's "The committed copy is the newest good state at every stage boundary — verified" false after this change; (b) for a new run the checkpoint is untracked at the first sweep, so the violation branch (`git rm -f` + `rmSync`, runner.ts:266–273) deletes it before the first `commitStage` and it is never committed until the terminal commit — the `git checkout HEAD -- …` repair printed in §3, the `loadState` repair message, and Test #13's "resume proceeds from the committed checkpoint" all point at content that never entered HEAD; (c) the same rule flags resume's own deletion of `ESCALATION.md` (runner.ts:1983–1989, the behavior §3 leans on), so the next sweep restores the marker from `headBefore` and §3's split-record line in `status` misfires on every resumed run. No test in the Test strategy catches this: #2's "byte-identical to `headBefore`" assertion is exactly what the misfire produces. Fix: keep the `stagePathAllowed` rule for attribution and reporting, but give the sweep a dedicated reserved-name branch that replaces the headBefore-restore behavior quoted in §1's third bullet ("the sweep restores the file from `headBefore` and removes the planted tree"): when a reserved name is dirty, untracked, or deleted at sweep time, restore it to the runner's authoritative content — re-save from the in-memory `PipelineState` via `checkpoint()` for `.pipeline.json` (which also overwrites a planted directory's remains after deleting the untracked tree), and re-apply resume's deletion for `ESCALATION.md` — instead of restoring from `headBefore` or removing it. Model-authored bytes still cannot survive the boundary, so the Q2 posture is preserved without reverting the runner's own writes.
- [minor][new] §2 "The cross-version resume contract" — "name the operator's two postures — resume with the pipeline that wrote it, or start a fresh run after archiving the run directory (ADR-006:55–57)" — the cited lines say a different pair: "the interim posture is operator-facing — a resume that straddles the merge of ADR-003 may need `git checkout HEAD -- docs/designs/<run>/.pipeline.json` or a fresh run." The first posture quoted appears nowhere in the ADR, and the ADR's first posture (restore the committed copy) is absent from the quoted pair; the refusal message and `docs/workflows.md` section (Rollout #3) will ship with an unsupported attribution. Fix: cite ADR-006:55–57 only as the precedent for naming operator postures in an error, and state the refusal pair as this design's own addition, or restate the pair to match the ADR's.
- [nit][new] §1 — "starts with `${STATE_FILE}.` (the `saveState` tmp pattern, `state-store.ts:186`)" — the prefix rule fences *any* name beginning `.pipeline.json.` at any depth, so a legitimate doc file (e.g. `docs/designs/<run>/.pipeline.json-notes.md`) can never be written by a stage. If the breadth is deliberate, keep it but say so in one sentence and pin Test #1 to a neighboring name like `.pipeline.json-notes.md` being forbidden too; otherwise match the tmp shape exactly (`/^\.pipeline\.json\.[0-9a-f]{8}\.tmp$/` on the last segment).
