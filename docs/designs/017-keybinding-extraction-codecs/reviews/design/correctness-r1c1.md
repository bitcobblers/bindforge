## Findings

The second tree's located files then appear in no document's `provenance.files` and its bindings are silently dropped — against §`bindings/v1`'s own "One JSON document per game per located user tree", against `017-C3`'s per-user document rule, and against `017-L3`'s honesty posture, while `--probe` still prints those files as located. The key also leaves the ordering law incomplete rather than finishing it: surviving same-`user` documents (distinct trees) still tie under "byte order by `user`", so #12's byte-identity premise is unpinned. No test catches the over-merge: #12's "two records that resolve the same user tree yield one document" passes under the wrong key too. Fix: key the dedup on the resolved `UserTree` anchor path (identity, never rendered) together with (`user`, `provenance.files`), so a tree is stated once per tree and two distinct trees under one label stay two documents; break the surviving `user` tie in the law by byte order over the serialized document; add one fixture (one slug in two libraries, two prefixes with different `Bindings`) asserting two documents and two `--probe` groups.
