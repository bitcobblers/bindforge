## Findings

- [major][new] §3 Chosen design, "Document families" bullet vs "Run-record block" bullet — the doc families are specified with two different run-record rule sets. "then trailing denies: `*transcripts*` and `*reviews*` over shell, `glob` and `grep` rules over `docs/designs/**/transcripts/**`" scopes their glob/grep denies to `transcripts/` only, while the next bullet appends the run-record block "to every shell-holding agent (… the five document families)" with "`glob` denies over `docs/designs/**/transcripts/**` **and** `docs/designs/**/reviews/**`; `grep` denies `*transcripts*` and `*reviews*`". An implementer cannot tell whether designer/editor/doc-sync get glob/grep denies over `reviews/**`. Additionally, under the proposal's own A17 semantics (grep resources are the requested regex, never a search path), a grep rule keyed to the path-shaped resource `docs/designs/**/transcripts/**` can never match — it is a dead rule; and if the transcripts-only reading governs, Decision 3 of the ADR ("`glob`/`grep` pattern rules for the same directories", i.e. both `transcripts/` and `reviews/`) is under-delivered for the document families. Fix: make the run-record block the single authority for the doc families' run-record denies (drop the narrower glob/grep clause from the first bullet, keeping its note that the `read` route to handed reports stays open), so one rule set per agent is specified.

- [major][new] §3 Chosen design, "Document families" bullet — the inspection set is written "(`cd`, `ls`, `cat`, `head`, `tail`, `wc`, `grep`, `rg`, `find`, `git status *`, `git diff *`, `git log *`, `git show *`)". Under the permission grammar the proposal itself relies on (A16/A17, and the permissions doc's Matching section — whole-value matching, with only the ` *` suffix additionally matching a bare command), a bare rule resource like `cat` or `wc` matches **only** the argument-less command `cat`/`wc`; every useful inspection command (`wc docs/designs/…/02-proposal.md`, `cat <path>`, `find …`) therefore stays denied behind the kept leading `shell * → deny`. As written, the widening buys nothing and silently defeats the ADR's stated purpose for Decision 3 ("so a proposal can check a path and a line count instead of asserting both"). The git entries carry stars; the rest do not — an inconsistency that reads as shorthand but is exactly the rule text an implementer copies. Fix: specify the star form for every entry (`cat *`, `ls *`, `wc *`, `find *`, `cd *`, … — or state "byte-identical to the inspection set already shipped in `code/coder.md`", the sentence the design panel bullet already uses), and have Test strategy #4 pin with-argument commands (`wc <file>` allowed), not bare names.

- [minor][new] §1 Chosen design, "Prompts" bullet — "the report at `{{reportPath}}` is yours — re-reading it is allowed" while the same section keeps "seat agents' `read` deny over `docs/designs/**/reviews/**` (A10) stays". The seat's only reachable re-read route is therefore `git diff`, and for a report written this attempt and not yet committed, `git diff <path>` on an untracked/unstaged file prints nothing — the prompt invites the seat to try the (denied) `read` tool first and burn a turn on a dead route, the exact friction class ADR-016 exists to stop. Fix: one clause naming the route and its audit-level meaning, e.g. "re-reading it is allowed (via your `git diff` allow — your `read` tool stays fenced off `reviews/`)".

- [minor][new] §4 Chosen design, "Document ceiling" bullet — "above the observed shipped artifacts (this run's `01-research.md` is 440 lines; the 012 proposal ~505)" states run-artifact line counts as fact, but they appear nowhere in the assumption register, unlike every other operator-observed number (A19/A20 register their class explicitly). Since `docMaxLines: 600` headroom is justified entirely by these counts, an unregistered miscount (a shipped artifact at >600) turns every normal full-flow run red at a document stage. Fix: add one register row (unverified, operator-observed: current artifact sizes behind the 600 cap) or drop the specific counts and cite the registry fixture evidence instead.

- [nit][new] §3 Chosen design — "Run-record block, appended last to every shell-holding agent" contradicts the next bullet's ordering "Own-report re-open, per seat agent **after the deny**": the re-open must come after the block, so the block is not last. Fix: say "appended after all other rules except the per-seat own-report re-open".
