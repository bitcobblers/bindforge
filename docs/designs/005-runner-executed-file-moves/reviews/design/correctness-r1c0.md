## Findings

- [major][new] Chosen design, "Read-only git for implement/fix/test-update seats (item 5)" — "`git status --no-optional-locks*` (the pinned form avoids the index-refresh side effect and the lock contention with the runner's own git calls, A6)" — the pinned form is the wrong spelling: git(1)'s synopsis lists `--no-optional-locks` among the options that precede `<command>`, it appears nowhere in git-status's own OPTIONS list, and git-status's BACKGROUND REFRESH section spells the remedy `git --no-optional-locks status`; the run's own 01-research.md agrees ("equivalently `git --no-optional-locks`"). As written, the only permitted `git status` form is one git-status rejects with "unknown option" (unknown options are fatal in git's parse-options), so the goal "The coder and test-engineer seats can run `git status`" is not delivered as pinned, and the proposal's assertion that the pin avoids the index refresh is false for the flag position shown. Fix: replace the allow entry with `git --no-optional-locks status*` (documented git(1) spelling); the deny refinements and the rest of the allowlist are unchanged.
- [minor][new] Chosen design, same section — "review seats already run the same three of four, code-correctness.md:27-31" — the cited file (and every other agent config) carries exactly two of the four named commands: `git diff*` and `git log*`; design-review seats carry only `git diff*`; `git show*` and `git status*` appear in no agent definition (grep over .opencode/agents). The precedent still holds, the count does not. Fix: change to "the same two of four (`git diff*`, `git log*`)".
- [minor][new] Chosen design, "Validator" rules 5/7 — "Containment: the realpath of `from` and of `to`'s nearest existing ancestor stay inside the repo's realpath" — the phrase "nearest existing ancestor" deliberately tolerates a `to` whose parent directory does not exist: such a pair passes every pre-flight rule, then deterministically fails at apply with `renameSync` ENOENT (rename(2): "a directory component in newpath does not exist"), is classified `moves-apply-failed: …` as "environmental — the model's reply was fine", which is false for this case, and skips the in-attempt nudge repair path, burning a fresh-session attempt and (for `fix`) a budget unit. ADR-005 item 2's own standard — check everything before touching anything — wants this in the validator, where it is a pure disk check. Fix: add to rule 5 "`to`'s parent directory exists on disk"; pins land in Test strategy #2's one-case-per-rule list.
- [nit][new] Assumption register, A13 — "saveState re-validates | verified | tools/orchestration/src/pipeline/state-store.ts:145-155" — that range is loadState's version gate and `StateSchema.safeParse`; saveState's re-validation is at 178-184 (research cites it correctly as 178-189). The claim is true; the row's basis range does not cover the saveState half. Fix: cite state-store.ts:145-155, 178-184.
- [nit][new] Assumption register, A6 — "`git status` refreshes the index by default | verified | https://git-scm.com/docs/git-log, https://git-scm.com/docs/git-diff, https://git-scm.com/docs/git-config" — the claim is true (git-status BACKGROUND REFRESH: "By default, `git status` will automatically refresh the index") but none of the three cited pages carries it; the source is git(1)/git-status(1). Fix: add https://git-scm.com/docs/git (or git-status) to the row's basis.
